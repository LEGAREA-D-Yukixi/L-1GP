# SkillCheck — スキルチェックシステム

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 受験者画面（TOP → 言語一覧 → テスト → 結果） |
| `admin.html` | 管理者画面（受験結果一覧・CSV出力） |
| `sc-core.js` | ロジック（バリデーション・出題生成・採点・本人確認・保存） |
| `sc-questions.js` | 選択式の問題データ（10言語 × 10問から4問出題） |
| `sc-code.js` | 記述式（写経）の問題データ（10言語 × 6問） |
| `config.js` | 設定（Supabase接続・出題数・合格ライン・本人確認方式） |

**6ファイルは常にセットで配置してください。**

## セットアップ

### 1. Supabase
1. 既存プロジェクト、または専用に新規プロジェクトを作成
2. 別途お渡しするSQLをSQL Editorで実行（テーブル・RLS・権限）
3. 管理者ユーザーを Authentication > Users から追加

### 2. config.js

Supabase の接続情報は**設定済み**です。そのままアップロードできます。

```js
SUPABASE_URL: 'https://yklwkovbphqmiucnmcmu.supabase.co',
SUPABASE_ANON_KEY: 'sb_publishable_...',
```

プロジェクトを変更する場合のみ書き換えてください。
キーは公開前提の publishable key です。anon に SELECT 権限を与えていないため、
Public リポジトリに置いても応募者データは読み出せません。

### 3. GitHub Pages
1. リポジトリ（例 `skill-check`）を作成
2. 5ファイル＋README.mdをアップロード
3. Settings > Pages > Source: `main` / `(root)`
4. 1〜2分待って `https://legarea-d-yukixi.github.io/skill-check/` を確認

**httpsで配信されていないと生体認証もカメラも動きません。**
ローカルの `file://` では動作しないため、GitHub Pages上で確認してください。

## 出題構成と配点

1言語あたり10問・**100点満点**です。

| 形式 | 問数 | 配点 | 採点 |
|---|---|---|---|
| 選択式 | 4問 | 1問10点（**40点**） | 提出時に自動採点。結果画面に即時表示 |
| 記述式（写経） | 6問 | 1問10点（**60点**） | 管理画面で担当者が0〜10点で採点 |

AWS の記述式は CLI コマンド・IAMポリシー・CloudFormation の写経です。

選択式は、AWS 以外は10問のプールから4問を抽選します。AWS はプールが4問なので毎回同じ4問が出ます。
変化を付けたい場合は `sc-questions.js` の `aws` に問題を足してください。
| **合計** | 10問 | **100点** | 記述式の審査がすべて終わると確定 |

合否は合計点で判定します（`PASS_LINE: 70` なら70点以上で合格）。
配点は `config.js` の `CHOICE_POINT` と `CODE_MAX` で変更できます。採点ボタンの数は `CODE_MAX` に追従します。

記述式は模範解答を解答欄の上に表示し、受験者がそのとおりに入力する形式です。
正しく写せているかの一致率を自動計算しますが、**点数は管理画面で人が付けます**。一致率は参考値です。

受験者の結果画面には選択式の点数（X / 40点）のみ表示され、記述式は「担当者が確認します」と案内されます。

### 管理画面での合計点

一覧に「合計」列があり、記述式の審査が終わった受験のみ `75 / 100点（75％）合格` の形で表示されます。
審査が済んでいないものは「審査待ち」と出ます。審査パネルでは0〜10の採点ボタンを押すたびに合計点が更新され、
全問に点を付けると合計・得点率・合否が確定します。保存すると一覧とCSVにも反映されます。

統計の「平均」「合格率」は審査済みの受験のみを対象に計算します。

## 録画と操作ログ

受験開始から提出までを記録します。録画が本人確認を兼ねるため、顔写真による本人確認はありません。

| 記録するもの | 保存先 |
|---|---|
| 画面（解答エリア）＋カメラ映像を合成した1本の動画 | Supabase Storage（`sc-recordings`） |
| 操作ログ（解答の変更履歴・貼り付け・画面離脱） | `sc_logs` テーブル |

受験前に「受験中の録画に同意します」のチェックが必要です。未チェックでは受験に進めません。

### 録画範囲

| `RECORD_AREA` | 範囲 | 備考 |
|---|---|---|
| `'screen'`（既定） | **画面全体** | 共有ダイアログで画面を選びます。ブラウザの外の操作も残ります |
| `'tab'` | このタブ | 共有ダイアログでタブを選びます |
| `'card'` | 受験カードのみ | 容量が最小 |

### 画面全体を録るときの位置あわせ

画面全体の映像には、ブラウザの表示領域がどこにあるかの情報が含まれません。
そのままでは解答欄の位置を計算できず、模範解答を隠せません。

そこで表示領域の四隅に**小さな目印**（左上・右下・右上の色付きの点）を置き、
映像の中からその色を探して「表示領域 → 映像」の対応を実測します。

測定結果は3点目の目印で検算し、次のいずれかに当てはまれば**使用しません**。

- 目印が見つからない
- 縦と横で倍率が5%以上ずれている
- 3点目が計算どおりの位置にない

使用しなかった場合は画面を録画せず、「ブラウザが映る画面を選び直すか、
『このタブ』を選んでください」と案内します。受験画面右上の
「画面の録画を開始」ボタンで、タブ共有に切り替えてやり直せます。

ウィンドウを動かされると対応がずれるため、位置とサイズを1.5秒ごとに監視し、
変化があれば測り直します。**測り直しが終わるまで画面は描きません。**

目印は録画にも小さく映ります。

### 答えが録画に映らない仕組み

| 形式 | 表示 | 録画での扱い |
|---|---|---|
| 記述式 | 模範解答を解答欄に薄い文字で重ねる | 解答欄ごと描画から除外し、**入力内容だけを描き直す** |
| 選択式 | 選択肢の下に「正解：B. …」を表示 | その欄を描画から除外する（白くなる） |

除外はクリップで行うため、該当のピクセルは canvas に一度も描かれません。
描き直すのは `textarea` の値だけで、模範解答の文字列は参照していません。
位置を特定できない場合は何も描かない作りです。

描き直しは実際の解答欄の見た目を計算スタイルから読んで再現します。
実画面と録画を同じ位置で切り出して比べ、**枠線の色・地色・文字の行位置が
1ピクセル単位で一致する**ことを確認しています。

| 揃えている点 | 内容 |
|---|---|
| 文字の行位置 | CSSの行ボックスと同じ計算（行の余りを上下に分け、その下にベースライン） |
| 枠線 | 太さを整数ピクセルに丸め、位置も整数に揃える（にじみ防止） |
| 地色・枠線色・角丸 | 計算スタイルから取得 |
| 入力中の光 | フォーカス時の外側の光も再現 |
| 穴の縁 | 座標を整数に丸め、1px広く塗ってクリップの継ぎ目を消す |

画面の映像は数フレーム遅れて届きます。いま測った位置で描くと、動いた直後だけ
映像と合わずに一瞬ずれて見えるため、位置の履歴を持ち、**映像が写しているであろう
少し前の位置**で描き直します（既定180ミリ秒）。動いている間は新旧の位置を
まとめた範囲を抜くので、はみ出しも起きません。解答欄の高さも固定にして、
問題を移ってもレイアウトが動かないようにしています。

### 解答欄の入力方式

日本語入力の変換候補はOSが描くため、ページ側からは位置も内容も掴めず、録画から除外できません。
そこで**変換候補そのものが出ない作り**にしています。

解答欄は `readonly` にしてあります。OSの日本語入力は「編集できる入力欄」に対してだけ
変換を始めるため、readonly なら変換候補が開きません。そのうえで打鍵を自分で拾って文字を差し込みます。

| 操作 | 扱い |
|---|---|
| 文字入力 | 半角英数のみ。全角英数・全角スペースは自動で半角に変換、それ以外は無視 |
| Backspace / Delete / Enter / Tab | 自前で処理（Tabは空白4つ） |
| 矢印キー / Home / End | 自前で処理（readonly ではキー操作でキャレットが動かないため） |
| Shift + 矢印 | 選択範囲の拡張 |
| 貼り付け・ドロップ | 禁止。試行は操作履歴に残る |
| コピー・全選択 | そのまま使える |

模範解答60問はすべて半角で書かれているため、そのまま写経できます。
問題名・指示文・解説は日本語のままです。

### 操作履歴

録画と並行して、受験中の操作を記録します。管理画面の審査パネルに一覧で表示され、
**注意が必要な操作は色付き**で目立つようにしています。

| 記録する操作 | 注意扱い |
|---|---|
| 問題の移動、選択式の解答、記述の編集、入力のクリア | － |
| 貼り付け、コピー、切り取り、右クリック | ○ |
| ショートカット（Ctrl/Cmd+C/V/X/A/S/F/P/U、F1〜F12、Esc） | ○ |
| 別タブ・別ウィンドウへの移動、画面外へのマウス移動 | ○ |
| 画面サイズの変更 | ○ |
| 録画の開始・終了・送信結果 | 失敗時のみ○ |

### 画質と容量

| 設定 | 既定値 |
|---|---|
| `RECORD_CANVAS_W` | 1280（撮影範囲の実寸が小さければそれに合わせる） |
| `RECORD_BITRATE` | 700000（約5MB/分） |
| `RECORD_FPS` | 8 |

キャンバスは撮影範囲の縦横比に合わせて作るため、黒帯なく全面を使います。
15分の受験で**約75MB**。Supabase 無料枠1GBでは**およそ13件**です。
件数を優先する場合は `RECORD_BITRATE` を下げてください（300000 なら約2MB/分、15分で30MB）。

Safari と Firefox は両APIとも未対応のため、**受験端末は Chrome または Edge（デスクトップ）を推奨します**。

### 使用するカメラ

`navigator.mediaDevices.getUserMedia` で取得します。カメラが2台以上つながっている場合はTOP画面に選択欄が出て、
外付けカメラを指定できます。選んだカメラは次回以降も記憶されます（`localStorage` の `sc_cam`）。

### 管理画面での審査

一覧の「審査する」から、録画の再生・操作ログの再生・記述解答の確認・採点ができます。
録画は一覧の「保存」からもダウンロードできます（ファイル名は `氏名_言語_日付.webm`）。

### 録画が始まる条件

画面共有の許可はタップ直後の短い間しか求められません。そのため言語を選んだ直後に、
**カメラより先に**画面共有を要求し、受験者情報の保存は待たずに走らせています。
録画の状態は受験画面の右上に表示されます。

### 録画が残らなかったときの確認

管理画面の審査パネルの録画欄に理由が表示されます。理由は操作ログから取得するのでSQLの追加は不要です。

| 表示 | 原因 | 対処 |
|---|---|---|
| 送信に失敗しました（コード 404） | バケットが無い | Storage に `sc-recordings` を作成 |
| 送信に失敗しました（コード 403） | 権限が無い | `storage.objects` の anon INSERT ポリシーを適用 |
| 送信に失敗しました（コード 413） | ファイルが大きすぎる | バケットのサイズ上限を引き上げる |
| 保存先に届いていません | 送信が記録されていない | コンソールと Storage 設定を確認 |
| 画面：共有の選択で… | タブ以外を選んだ | 共有ダイアログで「このタブ」を選ぶ |
| 録画が開始されていません | 同意なし、または非対応 | ブラウザを Chrome / Edge にする |
| 録画データが空でした | 映像が流れなかった | カメラの使用状況を確認 |
| 操作ログも保存されていません | DBへの保存自体が失敗 | テーブルと権限を確認 |

受験端末のコンソールでは `window.__lastRecBlob.size` で録画データが作られたか分かります。
0 または undefined なら録画そのものの失敗、サイズがあるのに管理画面に無ければ送信の失敗です。

### 動作確認の手順

Chrome で受験を開始し、次の2点を確認してください。

- 言語をタップした直後に画面共有のダイアログが出る → **「このタブ」を選ぶ**
- 受験画面の右上が「画面とカメラを録画中」になる

「カメラのみ録画中」の場合は画面共有が成立していません。管理画面に理由が出ます。

## 問題の追加・修正

`sc-questions.js` のみを編集します。

```js
{ q: '問題文',
  choices: ['選択肢1','選択肢2','選択肢3','選択肢4'],
  a: 1,              // 正解のインデックス（0始まり）
  exp: '解説文' },
```

記述式は `sc-code.js` を編集します。

```js
{ t: '問題名',
  task: '修正指示（〜してください。）',
  code: '修正前のコード',
  answer: '模範解答',
  exp: '解説' },
```

言語を追加する場合は `SC_LANGS` に1行足し、`SC_QUESTIONS` と `SC_CODE` に同じ `key` で配列を追加します。
